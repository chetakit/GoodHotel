# Good Hotel

ระบบจองและบริหารโรงแรม สำหรับลูกค้า และพนักงาน 4 ฝ่าย ได้แก่ พนักงานต้อนรับ แม่บ้าน ฝ่ายบัญชี และผู้ดูแลระบบ

ASP.NET Core MVC (.NET 10) · Entity Framework Core 9 · MySQL บน Railway

---

## ลงเครื่องใหม่

1. ลง **.NET 10 SDK** จาก https://dotnet.microsoft.com/download (ถ้ายังไม่มี)
2. Clone แล้วรัน

   ```bash
   git clone https://github.com/chetakit/GoodHotel.git
   cd GoodHotel
   dotnet run
   ```

3. เปิด http://localhost:5022

`appsettings.json` มีข้อมูลเชื่อมฐานข้อมูล Railway อยู่แล้ว จึงไม่ต้องตั้งค่าอะไรเพิ่ม
repo นี้เป็น **private**: ถ้าจะเปลี่ยนเป็น public ต้องเปลี่ยนรหัสฐานข้อมูลใน Railway ก่อน เพราะรหัสเดิมอยู่ในประวัติ git

## แต่ละบทบาททำอะไร

**ลูกค้า**
- ค้นหาห้องว่างตามวันที่และจำนวนคน แล้วจอง
- ระบบเลือกโปรโมชันที่ลดได้มากที่สุดให้อัตโนมัติ ไม่ต้องกรอกโค้ด
- ชำระเงินภายใน **15 นาที** หลังจอง ถ้าไม่ชำระ การจองจะถูกยกเลิกอัตโนมัติ
  - ช่องทาง: โอน, พร้อมเพย์, PayPal (จำลองทั้งหมด) หรือเลือกจ่ายเงินสดที่โรงแรม
- ดูการจองของฉัน ยกเลิกการจองได้ก่อนวันเข้าพัก ถ้าจ่ายแล้วระบบส่งคำขอคืนเงินให้เอง

**พนักงานต้อนรับ**
- หน้าหลักแสดงแขกที่จะเข้าวันนี้และแขกที่ต้องออก
  - เช็คอิน / เช็คเอาท์ได้จากหน้าหลักเลย
- รับลูกค้า Walk-in: จอง รับเงินสด และเช็คอินในขั้นตอนเดียว
- ยืนยันการรับเงินและตรวจสลิป
- ดูสถานะห้องจริง และตรวจห้องหลังแม่บ้านทำความสะอาด
- แจ้งซ่อม

**แม่บ้าน** (หน้าจอออกแบบให้ใช้บนมือถือได้)
- งานทำความสะอาดเข้ามาเองเมื่อพนักงานเช็คเอาท์ลูกค้า
- กด "รับงานและเริ่มทำ" แล้ว "ทำเสร็จแล้ว"
- แจ้งซ่อม และดูประวัติงาน

**ฝ่ายบัญชี**
- ภาพรวมรายได้วันนี้ / เดือนนี้ / ทั้งหมด
- ปิดยอดรายวัน: ทุกรายการรับและคืนเงิน พร้อมชื่อคนที่ยืนยัน
- อนุมัติหรือปฏิเสธการคืนเงิน และตรวจข้อมูลการชำระเงินเก่า
- รายงานการเงินตามช่วงวันที่ และดาวน์โหลด CSV

**ผู้ดูแลระบบ**
- จัดการห้องพัก โปรโมชัน บัญชีผู้ใช้ และพนักงาน
- ดูแลงานซ่อม: เริ่มซ่อม / ปิดงาน
- รายงานภาพรวมงานของโรงแรม
- ไม่ยุ่งเรื่องเงิน (เห็นแค่ยอดรวม) เพื่อแยกหน้าที่กับฝ่ายบัญชี

## ขั้นตอนหลักของระบบ

```
ลูกค้าจอง ──► ชำระเงินภายใน 15 นาที ──► พนักงานเช็คอิน ──► พนักงานเช็คเอาท์
                 │ (ไม่จ่าย = ยกเลิก)                           │
                 ▼                                              ▼
       ฝ่ายบัญชีเห็นในสมุดรายวัน               งานทำความสะอาดเข้าไปหาแม่บ้าน
                                                                │
                                                                ▼
                                    แม่บ้านทำเสร็จ ──► พนักงานตรวจห้อง ──► ห้องว่างให้จองใหม่
```

สถานะห้องที่แต่ละฝ่ายเห็น คิดจากข้อมูลจริงทั้งหมด ได้แก่ การเข้าพัก งานทำความสะอาด งานซ่อม และการจองของวันนี้ ไม่ได้มาจากการกรอกเอง

## ฐานข้อมูล

ฐานข้อมูลบน Railway มีครบทุกตารางแล้ว ไฟล์ SQL ในโปรเจคเป็นการเปลี่ยนโครงสร้างที่รันไปแล้วตามลำดับ:

| ไฟล์ | ทำอะไร |
|---|---|
| `add-booking-status.sql` | สถานะการจอง (จองแล้ว / ยกเลิก) |
| `add-promotion-rules.sql` | เงื่อนไขโปรโมชันแบบใหม่ |
| `add-booking-payment-deadline.sql` | เวลาที่จอง และเหตุผลที่ยกเลิก (กำหนดเวลาชำระเงิน) |
| `reset-demo-data.sql` | **ล้างข้อมูลทดสอบ** ก่อนสาธิต: ลบการจองและงานทั้งหมด (กดสำรองข้อมูลก่อน) |

ช่อง Query ของ Railway รันได้ครั้งละ 1 คำสั่ง ให้วางทีละคำสั่ง

## ตั้งค่า

**ปรับเวลาชำระเงิน** (เช่น ตอนสาธิตให้เห็นการยกเลิกอัตโนมัติเร็วขึ้น) ใส่ใน `appsettings.json`:

```json
"Booking": { "PaymentWindowMinutes": 1 }
```

ไม่ใส่ = 15 นาที ระบบเช็คการจองที่หมดเวลาทุก 30 วินาที

## โครงสร้างโปรเจค

```
Controllers/   หน้าเว็บของแต่ละบทบาท (Home = ลูกค้า, Staff, Housekeeper, Accountant, Admin, Payment, Maintenance)
Services/      กติกาของระบบ เช่น การจอง ห้องว่าง การชำระเงิน กำหนดเวลาชำระ งานทำความสะอาด
Models/        ตารางในฐานข้อมูล และข้อมูลที่ส่งไปแสดงผล
Views/         หน้าเว็บ (Shared/_Layout = หน้าลูกค้า, Shared/_BackOffice = หน้าพนักงานทุกบทบาท)
wwwroot/       CSS / JavaScript / รูปภาพ
Tests/         โปรแกรมทดสอบระบบชำระเงินและงานซ่อม
```

**หมายเหตุเรื่องความเร็ว:** ฐานข้อมูลอยู่บน Railway คุยกันแต่ละครั้งใช้ราว 0.2–0.4 วินาที โค้ดจึงรวม query ให้น้อยรอบที่สุด และยิง query ที่ไม่ขึ้นต่อกันพร้อมกัน (`ParallelReader`)
