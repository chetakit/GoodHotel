# Good Hotel

ระบบจองและบริหารโรงแรม สำหรับลูกค้า และพนักงาน 4 ฝ่าย ได้แก่ พนักงานต้อนรับ แม่บ้าน ฝ่ายบัญชี และผู้ดูแลระบบ

ASP.NET Core MVC (.NET 10) · Entity Framework Core 9 · MySQL บน Railway

---

## ลงเครื่องใหม่

1. ลง **.NET 10 SDK** จาก https://dotnet.microsoft.com/download (ถ้ายังไม่มี)
2. Clone

   ```bash
   git clone https://github.com/chetakit/GoodHotel.git
   cd GoodHotel
   ```

   repo เป็น private ต้องได้รับเชิญก่อนจึงจะ clone ได้
3. รัน แล้วเปิด http://localhost:5022 (ใช้ Chrome หรือ Edge)

   ```bash
   dotnet run
   ```

> `appsettings.json` มากับ repo และมีรหัสฐานข้อมูลจริง **ห้ามเปลี่ยน repo เป็น public** และห้ามส่งไฟล์นี้ต่อให้คนนอกทีม

## แต่ละบทบาททำอะไร

- ทุกบทบาทเปลี่ยนรหัสผ่านของตัวเองได้ (พนักงาน: มุมล่างซ้าย หรือกดที่ชื่อบนหน้าเว็บลูกค้า · ลูกค้า: "บัญชีของฉัน")
- ลูกค้าแก้ชื่อตัวเองได้ ส่วนชื่อพนักงานให้ผู้ดูแลระบบแก้ที่หน้า "บัญชีผู้ใช้"
- พนักงานที่เปิดหน้าเว็บลูกค้าอยู่ กดที่ชื่อมุมขวาบนเพื่อกลับหน้าทำงาน (เช่น Admin Management)

**ลูกค้า**
- ค้นหาห้องว่างตามวันที่และจำนวนคน ดูรายละเอียดห้องและปฏิทินวันว่าง แล้วจอง
- "บัญชีของฉัน": แก้ชื่อและเบอร์โทร (อีเมลและวันเกิดแก้เองไม่ได้) และหน้า "เกี่ยวกับเรา" บอกวิธีจองและเงื่อนไข
- โปรโมชัน: ระบบเลือกโปรที่ลดได้มากที่สุดให้เป็นค่าเริ่มต้น เปลี่ยนเองได้จาก dropdown (ไม่ต้องกรอกโค้ด)
- ชำระเงินภายใน **15 นาที** หลังจอง ถ้าไม่ชำระ การจองจะถูกยกเลิกอัตโนมัติ
  - ช่องทาง: โอน, พร้อมเพย์, PayPal (จำลองทั้งหมด) ชำระออนไลน์เท่านั้น ไม่มีจ่ายเงินสดที่โรงแรม
- เปิดใบเสร็จ (เลขที่ RC-xxxxxx) ของการจองที่ชำระแล้วได้ และพิมพ์ได้
- ยกเลิก / คืนเงิน
  - ยังไม่จ่าย: ยกเลิกได้ฟรี แล้วเลือกห้องอื่นวันเดิมได้ทันที
  - จ่ายแล้ว: **ขอคืนเงินได้ 1 ครั้งก่อนเช็คอิน** ฝ่ายบัญชีอนุมัติ → ยกเลิกการจองให้อัตโนมัติ / ปฏิเสธ → การจองยังอยู่ และเห็นเหตุผล
  - ยกเลิกเองได้ก่อนเช็คอิน แต่ไม่คืนเงิน (ระหว่างรอพิจารณาคำขอคืนเงิน ยกเลิกเองไม่ได้)
  - เมื่อฝ่ายบัญชีพิจารณาแล้ว หรือโรงแรมย้ายห้องให้ จะมีตัวเลขแจ้งเตือนที่เมนู "การจองของฉัน"
- เคยมาแบบ Walk-in แล้วสมัครสมาชิกทีหลังด้วยเบอร์โทรและชื่อ-นามสกุลเดิม: ระบบผูกเข้าบัญชีเดิม เห็นประวัติการเข้าพักครบ

**พนักงานต้อนรับ**
- หน้าหลักแสดงแขกที่จะเข้าวันนี้และแขกที่ต้องออก
  - เช็คอิน / เช็คเอาท์ได้จากหน้าหลักเลย
- รับลูกค้า Walk-in: จอง รับเงินสด และเช็คอินในขั้นตอนเดียว (เงินสดมีเฉพาะ Walk-in)
  - แสดงเฉพาะห้องที่พร้อมเข้าพักวันนี้ และบอกว่าแต่ละห้องออกได้ถึงวันไหน ถ้าไม่มีห้องว่างตามวันที่เลือก จะเสนอห้องที่พักได้สั้นกว่า
  - เลือกโปรจาก dropdown และดูสิทธิ์ของลูกค้าแต่ละโปรได้ พร้อมเหตุผลที่ใช้ไม่ได้
- รายการจอง: ค้นหาด้วยชื่อ เบอร์โทร หรือเลขที่ กรองตามสถานะและช่วงวันเข้าพัก และเลือกการเรียงได้ (ค่าเริ่มต้น เลขที่ใหม่ → เก่า)
- ยกเลิกการจองที่ยังไม่จ่ายแทนลูกค้าได้ (เช่น ลูกค้าไม่มา) การจองที่จ่ายแล้วให้ลูกค้าขอคืนเงินเอง
- ดูสถานะการชำระเงินก่อนเช็คอิน (จ่ายแล้ว / คืนเงินแล้ว) และเห็นคำเตือนเมื่อลูกค้ามีคำขอคืนเงินค้าง (เช็คอินแล้วคำขอถูกปิดอัตโนมัติ)
- ย้ายห้องให้การจองที่จ่ายแล้วแต่ยังไม่เช็คอิน (เช่น ห้องเสีย) ลูกค้าจ่ายเท่าเดิม ฝ่ายบัญชีเห็นใน Audit
- เลยวันออกแล้วไม่มีการเช็คอิน = "ไม่มาเข้าพัก" (กรองดูได้ในรายการจอง)
- ดูสถานะห้องจริง และตรวจห้องหลังแม่บ้านทำความสะอาด: ผ่าน หรือส่งกลับให้ทำใหม่พร้อมเหตุผล
- แจ้งซ่อม

**แม่บ้าน** (หน้าจอออกแบบให้ใช้บนมือถือได้)
- งานทำความสะอาดเข้ามาเองเมื่อพนักงานเช็คเอาท์ลูกค้า
- กด "รับงานและเริ่มทำ" แล้ว "ทำเสร็จแล้ว"
- แจ้งซ่อม และดูประวัติงาน
- งานซ่อมแสดงชื่อพร้อมตำแหน่งของคนแจ้งและคนปิดงาน เช่น "สมศรี รักสะอาด (แม่บ้าน)"

**ฝ่ายบัญชี**
- ภาพรวมรายได้วันนี้ / เดือนนี้ / ทั้งหมด
- ปิดยอดรายวัน: ทุกรายการรับและคืนเงิน พร้อมชื่อคนที่ยืนยัน
- พิจารณาคำขอคืนเงิน: อนุมัติ (บันทึกเงินคืน + ยกเลิกการจอง ห้องว่างทันที) หรือปฏิเสธพร้อมเหตุผลที่ลูกค้าเห็น
- หน้า Audit (ฝ่ายบัญชีและผู้ดูแลระบบดูได้): ไทม์ไลน์ทุกเหตุการณ์เรื่องเงินและการยกเลิก กรองตามวันที่ ประเภท ผู้ทำรายการ และเลขที่การจอง
- ตรวจข้อมูลการชำระเงินเก่า
- รายงานการเงินตามช่วงวันที่ และดาวน์โหลด CSV (มีเฉพาะฝ่ายบัญชี)

**ผู้ดูแลระบบ**
- จัดการห้องพัก โปรโมชัน บัญชีผู้ใช้ และพนักงาน
  - ตั้งห้องได้ 3 แบบ: เปิดขาย / ปิดขาย / ซ่อมบำรุง (ห้องมีแขกหรือไม่ ระบบดูจากการเช็คอินจริง)
- ดูแลงานซ่อม: เริ่มซ่อม / ปิดงาน
- หน้าห้องพักแสดงสถานะจริงเป็นป้ายสี
- รายงานภาพรวมงานของโรงแรม
- ไม่รับเงินและไม่อนุมัติคืนเงิน แต่ดูหน้า Audit ได้แบบอ่านอย่างเดียว เพื่อตรวจฝ่ายบัญชีอีกชั้น

## ขั้นตอนหลักของระบบ

```
ลูกค้าจอง ──► ชำระเงินภายใน 15 นาที ──► พนักงานเช็คอิน ──► พนักงานเช็คเอาท์
                 │ (ไม่จ่าย = ยกเลิก)                           │
                 ▼                                              ▼
       ฝ่ายบัญชีเห็นในสมุดรายวัน               งานทำความสะอาดเข้าไปหาแม่บ้าน
                                                                │
                                                                ▼
                                    แม่บ้านทำเสร็จ ──► พนักงานตรวจห้อง ──► ห้องว่างให้จองใหม่
```

ขอคืนเงิน (จ่ายแล้ว ยังไม่เช็คอิน):

```
ลูกค้าส่งคำขอ (1 ครั้ง) ──► ฝ่ายบัญชีพิจารณา ──┬─► อนุมัติ: บันทึกเงินคืน + ยกเลิกการจอง ห้องว่างทันที
     (ระหว่างรอ ยกเลิกเองไม่ได้)              └─► ปฏิเสธ: ลูกค้าเห็นเหตุผล มาพักตามปกติ หรือยกเลิกเองแบบไม่คืนเงิน
ถ้าเช็คอินระหว่างรอ ──► คำขอถูกปิดอัตโนมัติ        ลูกค้าเห็นตัวเลขแจ้งเตือนที่เมนู "การจองของฉัน"
```

สถานะห้องที่แต่ละฝ่ายเห็น คิดจากข้อมูลจริงทั้งหมด ได้แก่ การเข้าพัก งานทำความสะอาด งานซ่อม และการจองของวันนี้ ไม่ได้มาจากการกรอกเอง (สิ่งเดียวที่ Admin ตั้งเองคือเปิดขาย / ปิดขาย / ซ่อมบำรุง)

| สถานะห้อง | สี | จองเข้าพักวันนี้ | จองล่วงหน้า |
|---|---|---|---|
| ว่าง | เขียว | ได้ | ได้ |
| รอเช็คอิน | ม่วง | ไม่ได้ | ได้ ถ้าไม่ชนวันที่จองไว้ |
| มีผู้เข้าพัก | น้ำเงิน | ไม่ได้ | ได้ ตั้งแต่วันออกเป็นต้นไป |
| รอทำความสะอาด / รอตรวจห้อง | เหลืองส้ม | ไม่ได้ | ได้ ตั้งแต่พรุ่งนี้ |
| ซ่อมบำรุง | แดง | ไม่ได้ | ไม่ได้จนกว่าจะซ่อมเสร็จ |
| ไม่พร้อมขาย (Admin ปิด) | เทา | ไม่ได้ | ไม่ได้ |

- เช็คอินได้ตั้งแต่วันเข้าพักจนถึงก่อนวันออก และห้องต้องตรวจผ่านแล้ว
- เช็คเอาท์ก่อนหรือหลังกำหนดได้ (ไม่คืนเงินและไม่คิดเงินเพิ่ม) คนที่จองห้องต่อจะเช็คอินไม่ได้จนกว่าจะเช็คเอาท์และตรวจห้องผ่าน

## ฐานข้อมูล

ฐานข้อมูลบน Railway มีครบทุกตารางแล้ว ไฟล์ SQL ในโปรเจคเป็นการเปลี่ยนโครงสร้างที่รันไปแล้วตามลำดับ:

| ไฟล์ | ทำอะไร |
|---|---|
| `add-booking-status.sql` | สถานะการจอง (จองแล้ว / ยกเลิก) |
| `add-promotion-rules.sql` | เงื่อนไขโปรโมชันแบบใหม่ |
| `add-booking-payment-deadline.sql` | เวลาที่จอง และเหตุผลที่ยกเลิก (กำหนดเวลาชำระเงิน) |

ช่อง Query ของ Railway รันได้ครั้งละ 1 คำสั่ง ให้วางทีละคำสั่ง

### ข้อมูลตัวอย่างสำหรับสาธิต

```bash
dotnet run -- seed-demo --yes
```

- สำรองข้อมูลเดิมไว้ที่ `backups/` (ไม่ขึ้น GitHub) **ล้าง** แล้วตั้งข้อมูล 30 วันให้ตรงกับวันที่รัน (85 การจอง)
- ปิดเว็บก่อนรัน และควรรันเช้าวันสาธิต เพราะข้อมูลอิงจากวันที่รัน

## โครงสร้างโปรเจค

```
Controllers/   หน้าเว็บของแต่ละบทบาท (Home = ลูกค้า, Staff, Housekeeper, Accountant, Admin, Payment, Maintenance, Audit, Account)
Services/      กติกาของระบบ เช่น การจอง ห้องว่าง การชำระเงิน กำหนดเวลาชำระ งานทำความสะอาด
Models/        ตารางในฐานข้อมูล และข้อมูลที่ส่งไปแสดงผล
Views/         หน้าเว็บ (Shared/_Layout = หน้าลูกค้า, Shared/_BackOffice = หน้าพนักงานทุกบทบาท)
wwwroot/       CSS / JavaScript / รูปภาพ
Migrations/    ประวัติโครงสร้างฐานข้อมูล
Tests/         โปรแกรมทดสอบระบบชำระเงินและงานซ่อม
```

**หมายเหตุเรื่องความเร็ว:** ฐานข้อมูลอยู่บน Railway คุยกันแต่ละครั้งใช้ราว 0.2–0.4 วินาที โค้ดจึงรวม query ให้น้อยรอบที่สุด และยิง query ที่ไม่ขึ้นต่อกันพร้อมกัน (`ParallelReader`) เปิดหน้าทั่วไปใช้ราว 0.2 วินาที ส่วนการบันทึก (จอง ชำระเงิน เช็คอิน) ใช้ราว 1–3 วินาที เพราะต้องล็อกห้องกันจองซ้ำ
